# 版本记录与需求迭代

## 可用于简历的数字

原项目 CHANGELOG 共 **27 个版本标题**，最高为 **v25**；包含 v1—v11、v12.1／v12.2／v12.3、v13—v25。最后一条版本日期为 2026-07-04。这里统计的是日志中的更新记录，不是 Git 提交数、应用商店发布次数或独立验收次数。

当前产品覆盖 Mac / iPhone 两端，提供写作／整理／参照 3 种模式和 Markdown / TXT 两类资料；iPhone 编辑实现使用 1.2 秒延迟保存。模式数与格式数反映功能范围，延迟是配置参数，均不是用户效率提升数据。

## 怎样从个人需求推进

下表把实际功能变化与可解释的使用需求对应起来。需求解释依据功能与日志归纳，不冒充当时的逐字用户反馈，也不代表完成过多人访谈。

| 需求／遇到的问题 | 版本变化 | 能说明的产品判断 |
| --- | --- | --- |
| 先把正文写下来，再管连载进度 | v1 章节编辑与元数据；v2 状态与存稿统计；v3 手机预览与分段 | 先建立核心流程，再补进度管理和阅读检查 |
| 同时推进多部作品，入口需要清楚 | v4 多作品书架；v5 从网页／本地服务转向 Mac 原生应用；v6 快捷键与快照 | 从单一页面发展为日常使用工具，加入保存安全 |
| 管理栏挤占正文，资料需要边写边看 | v9 按需隐藏栏位；v12.1 分类资料与右侧参照；v24 三种任务模式 | 围绕写作任务组织界面，而非把所有功能常驻屏幕 |
| 希望在手机上补写，回电脑继续 | v13 协同雏形；v14 iPhone 工程；v15 统一文件位置；v19 同步等待与刷新 | 区分电脑完整写作与手机轻编辑，处理设备间文件位置与可读时机 |
| 编辑出现卡顿感、跳动或选区干扰 | v16 原生手机编辑器；v17 缓冲与延迟保存；v22—v23 调整选区、样式刷新与统计 | 迭代重点从“增加功能”转向输入稳定和保存反馈；无量化性能实测 |
| 复杂资料工具偏离核心任务 | v11 曾升级关系网／大事记；v20 移除两端相关入口；v21 回退 Mac Timeline | 展示功能试验与收缩的过程；没有使用率数据，不宣称由统计证明 |
| 需要更快找到资料，并兼容已有 TXT | v25 命令盘、MD／TXT 标识、新建与导入 TXT | 让已有资料进入写作流程，保留文件原格式 |

## 面试可讲的闭环

以“正文与资料切换”为例：发现写作时频繁查设定的需求 → 先允许栏位隐藏 → 增加资料分类与右侧参照 → 进一步按任务拆为三种模式 → 用命令盘查找资料并直接参照 → 用虚构工程现场展示路径。这个过程能通过日志与当前界面核对，不需要虚构“效率提升 50%”。

以“功能取舍”为例：曾尝试人物关系网、大事记与时间线 → 后续移除相应入口 → 将资源集中在章节编辑与资料参照。若本人能回忆具体使用困扰，再补充当时为何放弃；不要编造访谈或使用频次。
